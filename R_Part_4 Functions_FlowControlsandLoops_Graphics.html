Functions, Flow Controls & Loops, and Graphics

Functions

“Abstracting your code into many small functions is key for writing nice R code.”

Remember the concept of functions from school?

If we plug in 3 for the above function, we will get 27. Easy-peasy.

Code functions in R work the same way - there are inputs, there are actions that take place with those inputs inside the function, and then there are outputs.

For example:

sum_of_squares <- function(x,y){
  temp <- x^2 + y^2
  return(temp)
}
  • sum_of_squares(2,1) 
      ## [1] 5
  • sum_of_squares(y=1,x=2) 
      ## [1] 5

Keep in mind that the environment within a function only exists inside that function, unless you assign an output. Therefore, any variables created in a function cannot be used outside of it without you explicitly returning them. Also, anything to be used in the function needs to be included as an input.

Functions are incredibly useful!

  • If you have code that you want to package so that you can easily use it on many different datasets, lists, etc.
  • If you want to use a function on a new dataset, you only have to update the function call.

You can think of a function as saved code that performs an action. Super useful!

Flow controls

If(){else} and ifelse()

a <- -1

if (a >= 0) {
      sqrt(a) # sqrt() is used to calculate the square root
    } else if (a >= 1000000) {
      paste0(a, " is too large to calculate.")
    } else {
      paste0(a, " is a negative number.")
}
## [1] "-1 is a negative number."

If you only have two cases, then ifelse() will be faster:

ifelse(a >= 0, sqrt(a), paste0(a, " is a negative number."))
## [1] "-1 is a negative number."

ifelse() can also deal with multiple cases by using nested statements, but you need to be careful when applying to different types of data (i.e. if you have multiple cases, it is safer to use if(){else}:

ifelse(a >= 0, sqrt(a), ifelse(a >= 1000000, paste0(a, " is too large to calculate."), paste0(a, " is a negative number.")))
## [1] "-1 is a negative number."

Flow controls

For loops

This logic (and code) is very comparable to what we were doing with VBA.

For example, what if we want to calculate the summation of 1 to 10 in a loop?

sum <- 0
for (i in 1:10) {
  sum <- sum + i
}
  • sum 
      ## [1] 55

To make it more useful, we can include variables in the range of the index:

low <- 3
high <- 6

sum2 <- 0
for (i in low:high) {
  sum2 <- sum2 + i
}
  • sum2 
      ## [1] 18

Even easier, we can use a pre-defined vector as the range of index:

index_seq <- c(2, 6, 10, 22)

sum3 <- 0
for (i in index_seq) {
  sum3 <- sum3 + i
}
  • sum3 
      ## [1] 40

Graphics

Scatter plots

x <- 1:6
y <- c(2, 3, 1, 6, 2, 4)

Creating a simple scatter plot:

plot(x, y)

Adding some more elements to the plot:
* The main argument defines the title
* The xlab and ylab arguments define the label for the x and y axis, respectively

plot(x, y, main = "Plot of x and y", xlab = "variable x", ylab = "variable y")

Regression lines

Use abline() to add a regression line to our plot: Note that lm stands for “linear model”

plot(x, y, main = "Plot of x and y", xlab = "variable x", ylab = "variable y")
abline(lm(y ~ x))

Histograms

NOTE: When modeling, we will often want a random selection of the data in order to reflect the best proxy of a true full dataset. When doing random selection, it is often helpful to use seeding. This will allow for peer review as well as the capability to reproduce the same model, if necessary. This is done by using the set.seed() function.

Let’s practice this for the creation of an example histogram, which we can do by using the hist() function:

set.seed(1) # fix a set of random numbers
y <- rnorm(1000) # use rnorm() to generate 1000 random points that follow a standard normal distribution
hist(y, breaks = 50) # creates a histogram of y, with 50 bins

Use par(mfrow = c(nrow, ncol)) to create multiple graphs in one:

x <- 1:6
y <- c(2, 3, 1, 6, 2, 4)

par(mfrow = c(2, 2)) # specify this par() before any graphs, create a 2x2 grid
plot(x, y)
set.seed(0)
hist(rnorm(1000))
par(mfrow = c(1, 1)) # reset back to single graph after you finish

Loading and using packages

R is incredibly useful because of its built-in statistical capabilities, but is also incredibly versatile because of its crowdsourced nature. Professors and professionals from all over the world are constantly inventing new and improved ways to code processes. As a result, this world community creates super convenient things called packages. Packages roll together many useful functions for you to access, making coding substantially easier.

For example, the stats package or the dplyr package help to aid in data manipulation.

You can take a deep look into what packages contain by using vignette().

Try it out for dplyr by typing into your Console vignette("dplyr")

  • To see the list of installed packages, run installed.packages() in your console or go to the “Packages” tab in the Viewer pane.

  • When you start an R session, you automatically have several necessary packages loaded to your environment: stats, graphics, utils, and a few others.

Loading and using packages

Say you want to use the count function from the dplyr package, once you’ve installed it on your machine. You can try the following:

count(iris)   # Note: iris is a dataset that already exists in the R environment

This doesn’t work because there is no count() function in base R.

Usually you do not need to use just one function at a time from a package. To save some keystrokes then, we usually load the packages we need when we start working or at the top of a script, like this:

library(dplyr)
count(iris)

This tells R to attach the dplyr package to your environment. Once that happens, all the objects in the package (mostly functions) will also be attached or ‘loaded’ and made accessible to you without explicit package references in the function call.

Alternatively, you can supply the package name wherein the count function exists like this:

dplyr::count(iris)

This tells R to go to the libpath, find the package called dplyr, and find the function within there called “count”. This is especially useful when you have multiple packages with the same function names.

  • For any packages that are not installed already, you can run install.packages("my_package").
