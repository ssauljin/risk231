Issues with the dataset

It is very likely that the dataset that you need to analyze in reality is quite messy, which requires a careful examination and pre-processing if needed. Let us explore existing issues with given dataset as follows.

1. Possible associations among the covariates (which is called ‘co-linearity’ in Statistics)

Consider the descriptions of the following covariates:

  • DRSPLTY_M18: It means the specialty code of the doctor (only available if the outpatient visit was with a doctor),
  • MEDPTYPE_M18: Type of medical practitioner for the visit (if -1, then it means a doctor),

you can recognize that DRSPLTY_M18 and MEDPTYPE_M18 are somewhat conflicting so that their (negative) association will be high, which requires more careful analysis.

2. Existence of too many categories for a covariate

If you look at the definition of DRSPLTY_M18 from the codebook, you can check that there are at least 16 categories of medical practitioners. So, if you are trying to fit a linear model using such variable without any pre-processing, the fitted model could be neither interpretable nor to provide acceptable prediction performance.

3. Missing values

You can see that there are some missing values in each of the covariates. We need to think about whether we would just remove all records with missing values, or do something with them. Further, we also need to decide whether all missing values are equally treated or not [REFUSED (-7) vs DK (-8)].

Available methods

As such, basically you have two choices here.

  • Use a relatively simpler model that could require ‘extensive’ data pre-processing. [e.g. Generalized Linear Models (GLMs)]
  • Use a more complex model that requires less data pre-processing but comes with less interpretability. [e.g. Classification and Regression Trees (CART), Random forest, Neural network, to name a few…]

GLMs

Suppose \(Y\) is the response variable (or target variable) that we want to analyze and/or predict, and \(\mathbf{x}\) is the covariates (or independent variable). In GLMS, we assume certain relationship between \(\mathbb{E}[Y|\mathbf{x}]\) and \(\mathbf{x}\) as follows: \[ \mathbb{E}[Y|\mathbf{x}] = g (\mathbf{x}\beta), \] where the function \(g\) depends on your choice. Generally, we assume \(g(z)=z\) (identity function) if \(Y\) seems to follow a normal distribution, and assume \(g(z)=\exp (z)\) if \(Y\) seems to follow a gamma or Poisson distribution.

As our response variable ‘Total_Charge’ is strictly positive and continuos, we will use a gamma distribution for the GLM (in short, gamma GLM) so that \(g(z) = \exp(z)\).

See Chapter 4.6 of ‘an Introduction to Statistical Learning’ (ISL) textbook (https://www.statlearning.com/) for more explanations on GLMs.

Data pre-processing for a gamma GLM

Here are the some modifications that I made on the available covariates \(\mathbf{x}\) for better interpretability and less dimension:

  • ‘DRSPLTY_M18’ was converted to ‘Doctor_Type’ (6 or 8: Family practitioners, -1: Non-doctor, others: Specialists)
  • I decided not to consider distinctions among the non-doctor practitioners, so ‘MEDPTYPE_M18’ was removed.
  • ‘VSTCTGRY’ was converted to ‘Care_Category’ (2: Diagnosis or Treatment or Others)
  • For ‘VSTRELCN_M18’ , ‘SURGPROC’ and ‘MEDPRESC’, I treated missing values as NO so that there are only 2 categories (YES or NO).
  • For ‘Telehealth’, I treated missing values as MISSING so that there are 3 categories (YES, NO, or MISSING) because it was completely missing for the observations from year 2019 (pre-COVID).

Note that data pre-processing is an open question so there is no ‘Right Answer’ usually. You just use your own insight and prior knowledge about the domain.

Random Forest

Recall that prediction from a CART model depends on a single tree. So you may want to grow more ‘trees’ and use all of them to make a decision. Random forest is such a concept to grow multiple trees to create a ‘forest’, and make a decision from the consensus of the forest.

Note that we do not want to grow identical trees for 1000 times to build our forest - so when you train a random forest, a random selection is applied in your dataset so only a part of the dataset is used each time to train each tree.

(https://www.researchgate.net/publication/356781515_What_makes_a_good_prediction_Feature_importance_and_beginning_to_open_the_black_box_of_machine_learning_in_genetics/figures)

Prediction performance

Lastly, we compare the prediction performance of the four fitted models with the MEPS dataset as follows.

pred.glm  <- exp(predict(fit.glm, refined_MEPS_test))
pred.tree <- predict(fit.tree, raw_MEPS_test)
pred.rf   <- predict(fit.rf, raw_MEPS_test)
pred.nn   <- compute(fit.nn, rawonehot_MEPS_test)$net.result

valtable <- rbind(
c(
RMSE(pred.glm, raw_MEPS_test$Total_Charge) ,
RMSE(pred.tree, raw_MEPS_test$Total_Charge),
RMSE(pred.rf, raw_MEPS_test$Total_Charge),
RMSE(pred.nn, raw_MEPS_test$Total_Charge)),
c(
  MAE(pred.glm, raw_MEPS_test$Total_Charge) ,
  MAE(pred.tree, raw_MEPS_test$Total_Charge),
  MAE(pred.rf, raw_MEPS_test$Total_Charge),
  MAE(pred.nn, raw_MEPS_test$Total_Charge)))

colnames(valtable) <- c("GLM", "CART", "RF", "NN")
rownames(valtable) <- c("RMSE", "MAE")

As you can see, it is somewhat unclear which model would be the most preferred as RMSE and MAE provide different conclusions (RF is most favored with MAE, whereas GLM or CART is better with RMSE). So in this case another judgement is needed based on the insight and preference of the modeler.

(Personally, I would prefer GLM as it has the best interpretability, better RMSE than RF, and has comparable RMSE and MAE as the CART - but it is my choice rather than a right answer.)
